# Технический аудит лабораторной №2 — вариант 2

## Объект проверки

Исходный проект этапа 3 с парсером формул, классической семантикой, K3, L3,
таблицами истинности, семантическими свойствами, следованием и экспортом варианта 2.
Проверка выполнена на Python 3.13.5 с pytest; целевая совместимость — Python 3.10+.

| Полный pytest (включая 290 прежних тестов) | **324 passed in 42.32s** |
| Отдельный генеративный/стрессовый прогон | **4.508s, без расхождений** |
| Сгенерированные корректные AST в стресс-прогоне | 50 000 |

Эталонная реализация расположена в `qa/reference.py` и использует отдельные
таблицы значений связок. Она **не вызывает** вычислительные функции `semantics.py`.
Генеративный прогон воспроизводим: seed `2026110701`.

### Синтаксис

Проверены приоритеты ¬ > ∧ > ∨ > →, левая ассоциативность, явные скобки,
сложные вложения, повторные отрицания, имена переменных с Unicode,
ASCII/Unicode-связки, ошибки токенизации, неполные выражения, лишние
операторы и скобки, ограничения длины и глубины. Каждый успешно созданный
AST сравнивается **структурно** после форматирования и повторного разбора.

Принципиально: `p -> q -> r` и `(p -> q) -> r` — **одно** AST по принятой
левой ассоциативности; `p -> (q -> r)` — другое. Аналогично совпадают
`p -> q -> (q -> q)` и `(p -> q) -> (q -> q)`, но не
`p -> (q -> (q -> q))`.

### Семантика

Проверены все строки таблиц ¬, ∧, ∨, → для классики, K3 и L3; в том числе
значения `1/2`, отрицание отрицания, идемпотентность, коммутативность
конъюнкции/дизъюнкции, законы де Моргана, границы результатов.
Отдельно проверено `p -> p` при `p=1/2`: в K3 — `1/2`, в L3 — `1`.

### Следование и интерфейс

Независимым перебором проверены пустой набор посылок, повторения,
несовместные посылки, отсутствие моделей, существование контрпримеров,
строгое выделенное значение `1`, индивидуальные R1–R4 и случайные наборы
посылок. Консольные проверки охватывают ошибки оценок, повторный ввод,
недопустимые команды, глобальный выход, превышение лимитов и сбой записи.

## Найденные проблемы и исправления

1. **Фиксированный символ схемы.** Универсальный `match_schema` исходно
   трактовал все переменные шаблона как метапеременные. Для схем, где `f`
   является фиксированным символом, это допускало ложные совпадения.
   Добавлен необязательный аргумент `fixed_symbols` с сохранением
   совместимости со старым интерфейсом. Для E из первой работы нужно
   передать `fixed_symbols=frozenset({'f'})`. Добавлены позитивные и
   негативные регрессионные тесты для повторного вхождения и фиксированного `f`.
2. **Выход из вложенных меню.** Команда `:exit` работала из главного меню,
   но не в форме ввода оценок или меню варианта. Добавлен общий обработчик
   ввода: теперь `:exit`/`:quit` работают на любом уровне без traceback.
3. **Ошибка файловой системы в интерактивном экспорте.** При отсутствии
   права записи `OSError` мог завершить консоль с traceback. Теперь ошибка
   выводится пользователю, после чего главное меню продолжает работу.

Потенциальную ошибку при превышении лимита полного перебора проверили:
исходная программа уже обрабатывала `AnalysisLimitError` и не выдавала
неполный результат за доказанный. Дополнительного исправления не потребовалось.

## Оставшиеся ограничения

- Случайные проверки не являются формальным доказательством корректности
  для бесконечного множества всех допустимых формул. Исчерпывающий перебор
  проведён для примитивных связок, малых структур и всех заданий варианта.
- Парсер ограничивает глубину вложения и размер формулы, семантический
  анализ — объём полного перебора; это защитные ограничения, а не логические
  ограничения математических систем.
- Скобочная запись **со всеми** скобками может оказаться слишком глубокой
  для повторного ввода при очень длинной плоской цепочке. Для обратимого
  форматирования следует применять `format_formula`.
- Программа использует классическую двухзначную модель с выбранными
  многозначными связками K3/L3 и выделенным значением 1 по методичке.
- Испытания выполнены в доступной среде. Отдельная реальная проверка
  на Windows/PyCharm и на всех версиях Python 3.10+ здесь не проводилась.

## Воспроизведение

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python -m qa.stress --formulas 50000 --invalid 10000 --relations 3000
python main.py --variant2
python main.py --export-results
python main.py
```

Данные длительного прогона — `qa/qa_stress_results.json`, независимые расчёты
варианта — `qa/qa_variant2_reference.json`. Полные таблицы для отчёта —
`results/variant2/`.
